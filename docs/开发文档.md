## 1. 架构总览

```
┌──────────────────────────── Windows 本机 ────────────────────────────┐
│  浏览器                                                              │
│    │ HTTP (127.0.0.1:8717, Basic 认证仅在公网侧)                      │
│  面板 campfire-panel（Go 单二进制，内嵌 Web UI）                      │
│    │  RPC：每行一个 JSON {"id","op","params"}                         │
│    │  SSH（golang.org/x/crypto/ssh）                                  │
└────┼─────────────────────────────────────────────────────────────────┘
     │  sshd → direct-streamlocal → /run/campfire/agent.sock
┌────▼──────────────────── 云服务器（Linux）──────────────────────────┐
│  Agent campfire-agent（systemd 常驻，unix socket 0660）               │
│    │  exec / systemd / 文件读写 / Lua⇄JSON                            │
│  dst-server（Master）        dst-server-caves（Caves）                │
│  /home/dst/dst-server        /home/dst/.klei/DoNotStarveTogether/...  │
└──────────────────────────────────────────────────────────────────────┘
```

四条设计原则：

1. **执行层放在云上**：面板只是遥控器，关掉本机电脑服务器照跑；面板自身不持有游戏状态，进程/存档/模组全由 Agent 操作。
2. **不占端口**：面板与 Agent 之间走 SSH 的 direct-streamlocal 直连 unix socket，不额外监听 TCP，不需要在安全组开新口。
3. **长任务一律 Job 化**：安装、更新、重建世界、回档、重启都可能跑几分钟，HTTP 立即返回 Job，前端轮询状态与日志。
4. **配置即文件**：面板侧 `panel.json`，Agent 侧直接读写 DST 的 ini/lua/json 文件；没有数据库迁移负担。

## 3. 一次请求的完整链路

以"一键更新全部模组"为例：

1. **前端**：`app.js` 里点按钮 → `fetch('/api/mods/update', {method:'POST'})`。
2. **面板路由**：`http.go` 用 `s.job(mux, "/api/mods/update", "mods.update")` 注册；handler 创建 Job（状态 `running`），起 goroutine 执行，立即返回 `{"job":{"id":"..."}}`。
3. **RPC**：goroutine 调 `rpc.Call("mods.update", params)`，把请求编码成一行 JSON 写进 SSH 会话的 stdin，`SetDeadline(100s)` 后读一行响应。
4. **SSH 通道**：`ssh.Dial("tcp", host:port)` 建连（15s 超时），再用 `client.Dial("unix", "/run/campfire/agent.sock")` 打开流。连接失败会丢弃缓存的 ssh.Client，下次调用重连。
5. **Agent**：`agent.go` 的 `switch req.Op` 命中 `case "mods.update"` → `mods.go` 执行：先做存档快照 → 逐个模组查工坊 → 下载到 `ugc_mods` 目录 → 修 `appworkshop_322330.acf` → 重建分片 `modoverrides.lua` → 需要时重启对应分片。
6. **回传**：Agent 返回 `{"ok":true,"result":{...}}` 或 `{"ok":false,"error":"..."}`；面板写进 Job 的 result/error。
7. **前端轮询**：`/api/jobs/<id>` 返回状态、阶段与日志；任务结束后前端提示"成功/失败 + 回滚入口"。

> 读操作的超时是 100 秒（早期是 15 分钟，导致面板卡死，见踩坑 E）；写操作全部走 Job，不受单次请求超时限制。

## 4. JSON 行协议

**请求**（面板 → Agent，一行一条，`\n` 结尾）：

```json
{"id": 1730621234567890, "op": "mods.list", "params": {"cluster": "MyDediServer"}}
```

**响应**（Agent → 面板，同样一行）：

```json
{"ok": true, "result": {"mods": [...]}}
{"ok": false, "error": "steam 下载失败: ..."}
```

约定：

- `id` 由面板生成（纳秒时间戳），Agent 原样带回，便于排查错配；
- `params` 用 `json.RawMessage` 按 op 各自解析；
- 未知 op 返回 `ok:false`，不 panic；
- socket 权限 `0660`，属组允许 `ops`（面板运行用户）访问；
- 面板侧连接为单连接复用，出错即丢弃重连，避免半死连接。

**op 全表**（与 `agent.go` 的 switch 一一对应）：

| 分类 | op |
|---|---|
| 连通性 | `ping`、`status`、`health.get` |
| 世界 | `clusters.list`、`clusters.activate`、`clusters.create`、`clusters.start`、`clusters.stop`、`clusters.remove` |
| 模组 | `mods.list`、`mods.detail`、`mods.setEnabled`、`mods.setConfig`、`mods.install`、`mods.remove`、`mods.update`、`mods.updateOne` |
| 工坊 | `workshop.lookup`、`workshop.resolve`、`workshop.image` |
| 世界生成 | `worldgen.get`、`worldgen.set`、`worldgen.regenerate`、`worldgen.snapshots`、`worldgen.snapshot`、`worldgen.restore` |
| 控制台 | `console.exec` |
| 任务 | `jobs.get`、`jobs.list` |
| 日志 | `logs.tail`、`logs.truncate` |
| 服务 | `service.restart`、`game.version`、`game.update` |

## 5. 面板 HTTP 接口

`http.go` 把接口分三类：

```go
// 同步 GET
s.get(mux, "/api/health", "ping")
s.get(mux, "/api/overview", "status")
s.get(mux, "/api/clusters", "clusters.list")
s.get(mux, "/api/mods", "mods.list")
s.get(mux, "/api/worldgen", "worldgen.get")
s.get(mux, "/api/logs", "logs.tail")
s.get(mux, "/api/health/report", "health.get")

// 长任务（返回 Job）
s.job(mux, "/api/clusters/create", "clusters.create")
s.job(mux, "/api/mods/update", "mods.update")
s.job(mux, "/api/worldgen/regenerate", "worldgen.regenerate")
s.job(mux, "/api/service/restart", "service.restart")
// ...

// 同步写
s.call(mux, "/api/console/exec", "console.exec")
s.call(mux, "/api/worldgen/save", "worldgen.set")
s.call(mux, "/api/mods/detail", "mods.detail")
// ...

mux.Handle("/", http.FileServer(http.FS(web)))   // 内嵌前端
mux.HandleFunc("/api/jobs/", ...)                 // Job 轮询
mux.HandleFunc("/api/image", ...)                 // 工坊封面代理
```

鉴权与只读在 `http.go` 中间层统一处理：本机回环请求免认证；`public_hosts` 命中的请求要求 Basic 认证，且 `read_only` 时拒绝一切非 GET。

## 6. 核心模块

### 6.1 clusters.go —— 世界生命周期

- systemd 单元固定两个：`dst-server`（Master）与 `dst-server-caves`（Caves）；端口槽位 Master 10999/27016/8766、Caves 10998/27017/8767。
- **优雅关服**：`gracefulStopShard()` 不用 `systemctl stop`，而是向分片 stdin 控制台发 `c_shutdown(true)`，等进程自己存档、注销登记行后退出（实测 33–35 秒）。这是 `E_ROWID_EXIST` 的根治手段——SIGTERM 秒级重启时 Klei 的登记行不释放。
- **启动顺序**（`bringUpCluster`，被 regenerate/restore/restart 复用）：
  1. 停 Caves → 停 Master → 等 2 秒；
  2. 起 Master → 等 `Online Server Started` + `Sim paused`；
  3. 等日志 `/Server registered via geo DNS/`（上限 8 分钟）；
  4. 起 Caves → 等 `World \d+\(Caves\) is now connected`（上限 8 分钟）。
- 顺序不能反：先 Master 注册、后 Caves 连接，否则出现 "no available shard"。

### 6.2 mods.go —— 模组管理

- 工坊解析走 `ISteamRemoteStorage`（不是 ISteamUGC），字段用字符串解析后再转数字。
- 文件必须落 `ugc_mods/<cluster>/<shard>/content/322330/<id>`；放 `mods/` 会被游戏清掉。
- 新世界缺 `appworkshop_322330.acf` 与 `downloads/` 目录时，启动会报 `ODPF failed 37`，需要预置。
- `modoverrides.lua` 是**分片级**的，同一模组在两片的配置分别写。
- 批量安装前必须快照；22 个内容模组同装的翻车记录见踩坑 D（单模组被禁用 3 万次、load 68、SSH banner 超时）。
- 成功判据不是"下载成功"，而是运行期 `grep -c 'Disabling workshop'` 为 0。

### 6.3 worldgen.go —— 世界生成

- 目录数据 `worldgen_catalog.json`：14 组 / 214 项，每项带 `scope`（forest/cave/both/global）、`phase`（generation/rules）、`shards` 等元数据，由 `catalog.go` 从 `tools/wg` 解包出的游戏脚本生成。
- 前端按 `scope` 过滤：地上页 174 项、洞穴页 78 项；提交时 `filterOverridesForShard` 丢弃不属于该分片的项并返回 `dropped` 列表。
- 预设规范化：`normalizePreset`（Caves→`DST_CAVE`，Master→`SURVIVAL_TOGETHER`）；保存时强制写入 `preset`。
- 写入前 `sanitizeCaveOverrides` 清掉从森林带过来的 `task_set` / `start_location` / `roads` / `layout_mode` / `wormhole_prefab` 默认值。
- 校验：读取后比对 `shardindex` 的 `location` 与期望类型，不一致时返回中文 `preset_hint`，前端显示红灯与一键修复。
- 重新生成：单分片模式只动该分片存档；旧存档先自动快照。

### 6.4 console.go —— 无 RCON 的控制台

- 服务端由包装脚本 `/usr/local/bin/campfire-shard-run` 启动：

  ```bash
  exec tail -n 0 -F /run/campfire/console/<shard>.cmd | exec ./dontstarve_dedicated_server_nullrenderer -console ...
  ```

- 下发命令：向 `.cmd` 追加一行，再追加 `print("CFM-<token>")`（命令）与 `print("CFD-<token>")`（完成标记）。
- 回读：按上次 offset 增量读 `server_log.txt`，去掉时间戳前缀后匹配 marker，25 秒超时；指令报错也能回读（如 `TheNet:GetServerGameTime` 返回 nil）。
- 包装脚本由 `bootstrapConsole` 自动安装并 `daemon-reload`，老服务器升级不需要手工改 unit。

### 6.5 luaconf —— Lua ⇄ JSON

- 读文件先剥 KLEI 魔数头（`stripKleiHeader`，`luaconf.go:349` 附近）；
- 手写解析 Lua 表，保留注释与键顺序，输出 JSON 给前端；
- 回写时按原格式生成，避免把 `leveldataoverride.lua` 写成非法文件（非法会导致无限重启）；
- `frequency_descriptions` 等表必须保留**第一次定义**，否则野火等选项会缺项。

### 6.6 snapshots.go —— 快照与回档

- 目录名 `save-YYYYMMDD-HHMMSS`，每分片保留最近 2 份；空目录删除；回档前把当前存档存成 `pre-restore-*`。
- 回档流程：停两分片 → 校验快照完整 → 换回存档区 → `bringUpCluster()` → 校验 `shardindex` 类型。
- 时间从目录名解析（`cp -a` 会保留旧 mtime，不能用来判断）。

## 8. 前端

- `index.html` 只提供骨架与导航（概览/世界/模组/世界生成/日志）；`app.js` 单文件 965 行，原生 JS + fetch，无构建步骤。
- 页面切换 `activateTab()`；只有概览页每 60 秒刷新 health，避免频繁打服务器。
- 长任务：发起后轮询 `/api/jobs/<id>`，把 `phase` 与日志渲染成任务卡。
- 深链接：`?shard=Caves|Master` 直达分片、`?mod=<id>` 直达模组详情、`?newworld=1` 直接打开创建向导。
- 所有持久化都在 Agent 侧；前端刷新不丢状态。

```bash

# 双平台产物
```

## 10. 扩展指南

### 加一个世界生成参数

1. `tools/wg` 从游戏脚本提取 → 更新 `worldgen_catalog.json`（`catalog.go`）；
2. `worldgen.go` 的字段映射/校验里加上新 key；
3. 前端无需改：目录是按 `groups/items` 渲染的，只要元数据齐全自动出现；
4. 验证：`worldgen.get` 能读回、`worldgen.set` 落盘、`grep` 存档文件确认。

### 加一个操作接口

1. `agent.go` 的 `switch` 加 `case "<op>"`，实现放对应模块文件；
2. `http.go` 决定用 `s.get` / `s.call` / `s.job` 注册路由；
3. 长任务直接复用 Job 框架，前端按 `/api/jobs/<id>` 轮询，无需新协议。

### 加一个页面

1. `index.html` 加导航项；`app.js` 加 `activateTab` 分支与 loader；
2. 数据全部走已有 `/api/*`，不要在前端直连 SSH。

### 改哪同步哪

| 改动 | 需要同步的位置 |
|---|---|
| 新增系统调用/命令 | `exec.go` + 权限（sudoers 或 systemd unit） |
| 新增 DST 文件读写 | `luaconf`（格式保真）+ 单元测试式真机校验 |
| 新增端口 | 安全组 + `cluster.ini` + 前端端口展示 |
| 新增配置项 | `main.go` flag + `panelConfig` + `loadConfig` 默认值 + README |

## 11. 排障入口

| 症状 | 先看 |
|---|---|
| 面板 500 / Agent 离线 | `journalctl -u campfire-agent`；`ls -l /run/campfire/agent.sock`；手动 `ssh ops@host` |
| 任务一直 running | `/api/jobs/<id>` 的 phase 与日志；对应 systemd 单元状态 |
| SSH `banner exchange` 超时 | 服务器 load（模组刷屏会到 68）、fail2ban 封禁 |
| `E_ROWID_EXIST` | 是否优雅关服；同 Token 重启间隔；参考设计文档 §22 |
| 洞穴连不上 | Caves 是否 `World generated`；Master 是否 `no available shard`；握手日志 |
| 模组不生效 | `grep -c 'Disabling workshop'` 必须为 0 |

更完整的故障库见 `docs/踩坑与解决办法.md`（A 环境网络 / B 脚本落地 / C 游戏本体 / D 模组 / E 面板工程 / F 目录生成 / G AI 协作 / H 洞穴生成 / I 控制台 / J 分片重连 / K 登记行）。

## 12. 已知限制

- 单用户、单世界同时运行（2C4G 只够一份双分片），无多租户；
- 无内建自动化测试与 CI——项目目标是先跑通，验收靠真机脚本与独立证据；
- 工坊无历史版本，模组回滚依赖"更新前快照"这一约定；
- 面板只监听回环地址，公网访问必须经反向代理 + Basic 认证 + 只读；
- 双分片常态内存约 3.1/3.5 GB（87%），扩容优先升 4C8G；
- Lua 解析器覆盖 DST 配置文件用到的子集，不是通用 Lua 实现。
