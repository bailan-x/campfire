# 踩坑与解决办法（Campfire / DST 专用服务器）

> 全部是本项目真机踩过的，按"现象 → 根因 → 解决"记录。搜索关键词优先看最后一列。

## A. 环境与网络

| 现象 | 根因 | 解决 | 关键词 |
|---|---|---|---|
| `ssh: Connection timed out during banner exchange`，但 ping / TCP 22 都通 | 服务器负载打满（当时 load 26→68），sshd 抢不到 CPU | 先查 `uptime`/`vmstat`；`wa` 高 + `kswapd0` 活跃通常是内存/swap 抖动；停掉吃内存的服务先救活 | banner, load |
| 面板报 `ssh: handshake failed: knownhosts: key mismatch` | Ubuntu sshd 会**先出示 ecdsa** 主机密钥，而 known_hosts 里只有 ed25519；Go 的 `knownhosts` 需要**同类型**条目（OpenSSH 客户端会自动挑 ed25519，所以 CLI 没问题） | 把服务器 `/etc/ssh/ssh_host_*_key.pub` 全部导出写进 known_hosts（4 条：dss/ecdsa/ed25519/rsa），文件必须 **LF、无 BOM** | knownhosts, key mismatch |
| `ssh` 能登但 `ls /home/dst` 报 Permission denied | `ops` 用户对 `/home/dst` 无权限（属主 `dst`） | 读配置/看日志一律加 `sudo` | 权限, /home/dst |
| 阿里云 Workbench 登录失败"用户名或私钥不正确或禁用了 root" | 加固时设了 `PermitRootLogin no` + `PasswordAuthentication no` | 用 `ops` + 密钥，或控制台 VNC；这是**预期行为**，不是故障 | Workbench, root |
| 国内直连 `steamcommunity.com` 超时，`api.steampowered.com` 通 | 前者被墙、后者可用 | 工坊元数据走 `api.steampowered.com`（无需 API key）；图片走 Agent 代理（`/api/image`） | 工坊, Steam API |

## B. 脚本落地（PowerShell ↔ Linux）

| 现象 | 根因 | 解决 | 关键词 |
|---|---|---|---|
| 远程命令被拼坏（`grep -E "a\|b"` 变成执行 dpkg、`bash: line 1: 1: ambiguous redirect`） | PowerShell 把 here-string 传给 `ssh` 会压平换行/吞引号 | **本地写 .sh → scp → 远程 `sudo bash /tmp/x.sh`**，不要内联长命令 | heredoc, 拼坏 |
| 脚本里所有字母 `r` 被删（`cluster.ini`→`cluste.ini`） | `ssh ... 'tr -d "\r" ...'` 里 `\r` 被 PowerShell 解释成 `r`，`tr` 于是删掉所有 r | 本地写**纯 LF 无 BOM** 文件（`[IO.File]::WriteAllText($p,$t,(New-Object Text.UTF8Encoding($false)))`），远程直接 `bash`，不用 `tr` | tr, \r |
| `sh: 29: STEAMCMD: not found` / `Syntax error: "(" unexpected` | PowerShell `Set-Content -Encoding UTF8` 给文件加了 **UTF-8 BOM**，shebang 失效、解释器变成 sh | 同上，用 `UTF8Encoding($false)`；已有文件用 `sudo sed -i '1s/^\xEF\xBB\xBF//'` 去 BOM | BOM, shebang |
| `pkill -f 'add-mods.sh'` 把 ssh 自己杀了 | `-f` 匹配整条命令行，包含 ssh 的远程命令串 | 用显式 PID `kill`，别用 `pkill -f` | pkill |
| `$host` 赋值报错 | PowerShell 的 `$host` 是只读自动变量 | 换成 `$node` / `$target` | $host |
| 中文 `echo` 在 .cmd 里报"不是内部或外部命令" | 控制台 GBK 代码页把 UTF-8 中文拆开 | .cmd/.bat 里只用 ASCII，中文留给 UI | cmd, 中文 |

## C. DST 服务端本体

| 现象 | 根因 | 解决 | 关键词 |
|---|---|---|---|
| 启动即 `DoLuaFile Could not load lua file scripts/main.lua` / `Error, failed to change working directory to ../data` | 程序会 `cd ../data`，工作目录必须是 `<install>/bin64` | systemd 里 `WorkingDirectory=/home/dst/dst-server/bin64` | WorkingDirectory, main.lua |
| 报缺 `libcurl.so.4` | 缺 32 位运行库 | `dpkg --add-architecture i386` + `lib32gcc-s1 lib32stdc++6 libstdc++6:i386 libcurl4-gnutls-dev:i386` | libcurl, i386 |
| 手写 `leveldataoverride.lua` → `[string "scripts/shardindex.lua"]:347: Level data override is invalid!`，无限重启 | 该文件是**游戏内部**完整关卡定义（需 id/name/desc/location/overrides 等字段），源码注释写明 `leveldataoverride is for GAME USE... worldgenoverride is for USER USE` | 用户可写的是 **`worldgenoverride.lua`**，合法字段只有 `overrides / preset / settings_preset / worldgen_preset / override_enabled`；改完删 `save` 重新生成 | leveldataoverride |
| 世界规则改了但进游戏没生效 | 世界生成参数只在**生成时**生效 | 删掉（或改名）`<cluster>/<shard>/save`，重启让游戏重新生成；旧存档先备份 | worldgen, 重新生成 |
| 地面洞口显示 disabled、下不去 | 洞穴入口 prefab 本身是"闭合岩石"，需要玩家挖开或激活，日志 `Validating portal[N] <-> 2[N] (disabled)` 属正常 | 游戏内用镐子挖开；两分片确实互通（`World 2(Caves) is now connected`） | portal, 洞穴入口 |
| 服务器列表里搜不到 / 发 A2S_INFO 无响应 | DST **不响应**标准 Steam A2S 查询，只回自己的 Klei 协议包 | 用游戏内搜索或 `c_connect("IP", 10999)` 验证；别拿 A2S 判定死活 | A2S, 搜不到 |
| 端口全开却连不上 | 端口没在安全组放行，或用了 27014/8764 这类**没放行**的端口 | 安全组放行 UDP `10998–11018`、`27015–27020`、`8766–8770`；新世界端口用"槽位分配"保证落在区间内 | 安全组, 端口 |

## D. 模组（最费时间的一块）

| 现象 | 根因 | 解决 | 关键词 |
|---|---|---|---|
| `Success. Downloaded item` 但服务器没加载模组 | 旧机制把 mod 放 `mods/workshop-<id>`，新版 DST 认为是 UGC 并**主动删除**，改从 `ugc_mods/<cluster>/<shard>/content/322330/<id>` 加载 | 下载落点 `steamapps/workshop/content/322330/<id>`，**同步落点必须是 ugc 目录**；判加载看 `Registering Mod workshop-<id>` 条数 | mods/ 为空, ugc_mods |
| 新建世界首启动把模组全部重下、`[Workshop] ODPF failed entirely: 37` | 新世界的 `ugc_mods/<cluster>/<shard>/` 缺 Steam 记录（`appworkshop_322330.acf` + `downloads/`） | 从已有世界同分片 `rsync` 复制 `appworkshop_322330.acf` 与 `downloads/`（面板已自动做） | acf, 重下 |
| 22 个内容模组一起装 → 整机卡死、load 68、SSH banner 超时 | 大改模组互相冲突，`error calling ComponentPostInit: pickable in mod workshop-2039181790 (Uncompromising Mode)` 触发"报错→禁用→重载"死循环（单个模组被禁用 3 万次），SSH 抢不到 CPU | 立刻 `systemctl stop dst-server` 救内存；**先只装工具类模组**，内容模组一次加一个、加完看 `grep -c 'Disabling workshop'` 是否为 0 | 模组冲突, 死循环 |
| 存档被模组污染（847 条 `SpawnSaveRecord ... FAILED`） | 关掉模组后旧存档引用的 prefab 不存在 | 回滚到加模组前的备份（`/home/dst/backups/`），或删档重开 | 存档污染 |
| `rsync: [receiver] mkstemp ... Permission denied (13)` | `mods/workshop-*` 目录是 root 建的，游戏用户 `dst` 写不进去 | rsync 前 `chown -R dst:dst` 目标目录 | rsync, Permission |
| 模组设置改了没生效 | `modoverrides.lua` 是**分片级**（Master、Caves 各一份），只改一份等于半个世界生效 | 两个分片都写；改完重启 | modoverrides |
| 纯客户端模组装到服务器上，客户端报错 | `client_only_mod=true` 的模组不需要装服务器 | 服务器只装服务端模组；`all_clients_require_mod=true` 的必须让朋友也订阅 | client_only |
| 工坊链接粘贴后查不到 | 直接访问 `steamcommunity.com` 被墙 | 走 `ISteamRemoteStorage/GetPublishedFileDetails`（匿名可用）+ 本地/服务器缓存 6 小时 | 工坊链接 |

## E. 面板与工程

| 现象 | 根因 | 解决 | 关键词 |
|---|---|---|---|
| `worldgen.get` 返回空 overrides | DST 配置里带魔数头 `KLEI     1 return { ... }`，Lua 解析器把它当标识符跳过整段 | `Parse` 入口先 `stripKleiHeader`（跳过 `KLEI` + 空格 + 数字） | KLEI, 解析 |
| `json: cannot unmarshal string into Go struct field ... file_size of type int64` | Steam Web API 把 `file_size/time_updated/subscriptions` 当**字符串**返回 | 用 `flexInt64`（去引号再 ParseInt，失败按 float） | Steam JSON |
| 面板整个卡死 120 秒，健康检查却正常 | RPC 隧道读超时设成 15 分钟，一个卡住的调用把后续全堵在互斥锁上 | 读超时 100 秒 + 失败即丢连接重连 | RPC 超时 |
| 模组列表加载 25 秒以上 | 每个模组实时查 Steam，国内网络 25 秒超时 × 3 次重试 | 工坊元数据落盘缓存（`<home>/.campfire/workshop-cache.json`，TTL 6 小时，只查缺失项） | 缓存 |
| 列表里出现 `string_format` / `function(` 这种乱码简介 | `modinfo.lua` 的 `description` 里是 Lua 片段 | `junkDescription()` 判定为碎片时改用工坊简介，并 `clipText` 截断 | 描述清洗 |
| 深链接 `#mods&?mod=x` 打开的是概览页 | `activateTab` 收到非法 tab 名回退到默认 | 正确形式 `?mod=<id>#mods`（query 在前，hash 在后） | 深链接 |
| 内嵌静态页 404 `pattern web: no matching files found` | `//go:embed web` 目录里没有文件 | 先把 `web/` 下的文件建出来再编译 | go:embed |
| `undefined: syscall.Statfs_t`（在 Windows 上编译） | 该符号只在 Linux 存在 | 拆 `sysinfo.go`（`//go:build linux`）+ `sysinfo_other.go` 桩 | 交叉编译 |
| Go 编出来的 Agent 起来就退出，日志 `not found` | systemd 里相对路径 / 权限问题；先 `journalctl -u campfire-agent -n 50` 看 | 用绝对路径 + `install -m0755`；socket 目录用 `RuntimeDirectory=campfire` | systemd |
| Agent 重启瞬间面板报 `读取隧道响应失败: EOF` | 连接被断 | 等 2 秒重试；面板会自动重连 | EOF |
| 改了 `worldgen_catalog.json` 但界面没变 | `go:embed` 是编译期打包 | 重新 `go build` 再部署 Agent | embed |

## F. 世界规则目录自动生成

| 现象 | 根因 | 解决 | 关键词 |
|---|---|---|---|
| "野火"只有"默认"、选不了"从不" | `customize.lua` 里 `frequency_descriptions` 先 `local` 声明、再在两个分支赋值；**else（主机）分支把 often/always 注释掉了**，后写覆盖前写 | 解析时**保留第一次出现的定义**（`IsNotConsole()` 分支选项最全） | choices 缺失 |

## G. AI 协作踩坑（AI 自身的操作方式造成的，不是 DST 的）

### G1. 知识幻觉 / 过时信息

| 现象 | 根因 | 解决 | 关键词 |
|---|---|---|---|
| 照"常识"写 `leveldataoverride.lua`，服务端无限重启 `Level data override is invalid!` | 模型语料把游戏内部文件当成用户配置入口 | 解包 `scripts.zip` 读源码（注释写明 `leveldataoverride is for GAME USE... worldgenoverride is for USER USE`），改 `worldgenoverride.lua` | 幻觉, leveldataoverride |
| 以为有 RCON，设计里写成 RCON 客户端 | 二手资料过时 | 查证后改 PTY + stdin；踢人是 `TheNet:Kick(userid)` 不是 `c_kick` | RCON |
| 用 A2S_INFO 探测服务器，一直"无响应" | DST 只回自己的 Klei 协议包 | 用游戏内搜索 / `c_connect` 验证；别拿 A2S 判定死活 | A2S |
| 以为模组放 `mods/workshop-<id>` 就加载 | 旧机制 | 真加载源是 `ugc_mods/<cluster>/<shard>/content/322330/<id>` | mods/ |
| 联网抓 `github.com` / `steamcommunity.com` / fandom 失败，调研有不可核验项 | 国内网络限制 | 优先用可核验源：Steam Web API、本地解包的 `.lua`、控制台实测；二手来源要标注 | 调研, 抓取失败 |

**纪律**：涉及游戏行为 → **源码 > 官方文档 > 模型记忆**。

### G2. "假完成"（自我报告 ≠ 事实）

| 现象 | 根因 | 解决 | 关键词 |
|---|---|---|---|
| 报告"已同步 22 个模组"，实际 `du mods/` 只有 34M、`ls` 只剩 1 个目录 | 只看自己的日志，没看磁盘 | 每条结论配一条**独立证据**：`du`/`ls`/`ss -lunp`/`grep -c`/接口返回/job 日志原文 | 假完成 |
| 接口返回"世界创建成功"，实际端口 10997/27014/8764 全在安全组外 | 只验证"调用没报错"，没验证"结果可用" | 验收标准写成"能进游戏/端口在放行区间"，并真机核对 `ss -lunp` | 验收 |
| `ModIndex: Load sequence finished successfully` + `Online Server Started` 就下结论"模组正常" | 这只能证明"加载过"，不能证明"运行期不炸" | 增加判据 `journalctl \| grep -c 'Disabling workshop'` 必须为 0；看 load / 内存曲线 | 健康判据 |

**纪律**：说"完成"之前，必须能贴出一条与代码路径无关的证据。

### G3. 用 shell 传多行文本 / 编码

| 现象 | 根因 | 解决 | 关键词 |
|---|---|---|---|
| ssh 远程命令被拼坏：`grep -E "a\|b"` 变成执行 `dpkg`/`rsync`，`bash: line 1: 1: ambiguous redirect` | PowerShell here-string 经 ssh 会压平换行、吞引号 | 本地写 `.sh` → `scp` → 远程 `bash`；**不通过 shell 传多行文本** | here-string |
| 脚本里所有字母 `r` 被删（`cluster.ini`→`cluste.ini`） | `tr -d "\r"` 里的 `\r` 被 PowerShell 变成 `r` | 直接写纯 LF 无 BOM 文件，不用 `tr` | tr |
| `sh: 29: STEAMCMD: not found`、`Syntax error: "(" unexpected` | `Set-Content -Encoding UTF8` 加了 BOM，shebang 失效 | `[IO.File]::WriteAllText($p,$t,(New-Object Text.UTF8Encoding($false)))`；已有文件 `sed -i '1s/^\xEF\xBB\xBF//'` | BOM |
| `pkill -f 'xxx.sh'` 把当前 ssh 会话杀掉 | `-f` 匹配整条命令行，含 ssh 的远程命令 | 用显式 PID | pkill |
| 赋值 `$host = ...` 报错 | PowerShell 自动变量只读 | 用 `$node`/`$target` | $host |
| 中文在控制台显示乱码，误判文件坏了 | 控制台 GBK 代码页 | 用 `[IO.File]::ReadAllText` 统计与校验；文件本身是 UTF-8 | 编码 |
| headless 截图打开的是概览页 | 深链接写成 `#mods&?mod=x`，`activateTab` 收到非法 tab 名 | 正确形式 `?mod=<id>#mods`（query 在前、hash 在后） | 深链接 |
| scp 后远端二进制跑不起来 | 移动网络传输中断/截断 | `md5sum` 与本地 `Get-FileHash` 比对，不一致就重试 | scp, md5 |

### G4. 协作与边界

| 现象 | 根因 | 解决 | 关键词 |
|---|---|---|---|
| 需求从"小程序"漂到"Web 面板"再到"本地面板+Agent"，文档一度按旧假设写 | 早期假设未及时确认 | 关键岔路用 `ask_user_question` 拍板；每次变更写进设计文档"变更记录"（v1.0→v2.5） | 需求漂移 |
| 用户说"先改文档、我没叫做就别动工"，下一轮却又开始写代码 | 长会话里约束只存在记忆中 | 把约束写成**上下文里的 open objective** + 文档里的前提表（"面板代码未获授权"）；每轮开工前回看 | 越权动工 |
| 长会话压缩后"昨天验证过什么"变模糊 | 上下文压缩丢细节 | 结论**当天落盘**（设计文档 §16/§17、交接说明、README），每轮先读文件不靠回忆 | 上下文压缩 |
| 为"一次做完"把 22 个内容模组一起装上 → load 68、SSH 登不上 | 批量操作没有回滚点与小步验证 | 批量前必备份、先冒烟、一次一个；已写进 Skill 第 4 节 | 批量事故 |

**纪律**：批量操作前先有回滚点；边界不清先问；结论当天写进文件。

### G5. 重来一次的 5 条总规矩

1. 源码 > 文档 > 记忆（涉及游戏行为先解包读 lua）。
2. 每个"完成"都要一条独立证据（磁盘/端口/日志计数/接口返回）。
3. 多行文本不过 shell：本地写文件 → scp → 执行。
4. 批量操作前必有备份 + 小步验证，尤其是"一键"类功能。
5. 结论当天落盘（文档 + 交接说明），AI 的记性靠文件不靠大脑。

## H. 世界生成：进洞穴却进了新的地上世界（2026-11-02）

| 现象 | 根因 | 解决 | 关键词 |
|---|---|---|---|
| 走到地面洞口下去，加载出一片**新的地上世界**，那片世界的洞穴也不可用 | `Caves/worldgenoverride.lua` 里**没有 `preset`** → 游戏 `shardindex.lua:520` 用 `GetDefaultWorldOptions(game_mode)` 得到森林默认关卡 | 洞穴分片必须写 `preset = "DST_CAVE"`（或 `DST_CAVE_PLUS`/`TERRARIA_CAVE`）、地上必须写地上预设；平台 `normalizePreset` 强制校验 + 世界生成页红色告警 | worldgenoverride, preset, DST_CAVE |
| 补了 `preset=DST_CAVE` 后仍然生成失败，日志 `PANIC: missing required prefab [moon_altar_rock_glass]! Expected 1, got 0`、`An error occured during world gen we will retry!` 无限重试 | 文件里残留**森林 location 的键**：`task_set="default"`、`start_location="default"`、`roads="default"`。这些是"森林世界被存进 Caves 分片"时游戏自己写回的（`mainfunctions.lua:997 UpdateWorldGenOverride` 写 `worldgen_preset`/`settings_preset` + `topology.overrides`，只删除"等于当前 location 默认值"的键），之后 `level.lua:92` 拿 `task_set` 去要森林任务集 | 把这些键清掉，只留 `preset` + 真正要改的规则；平台 `sanitizeCaveOverrides` 在 GET 时提示、保存/重新生成时自动清除 | task_set, moon_altar_rock_glass, UpdateWorldGenOverride |
