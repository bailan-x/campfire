# 通用化与替换点清单

> 目的：这套流程 80% 是"通用套路"，下次换机器/换世界/换游戏时可复用；这里是**哪些能通用**、**哪些必须替换**、**怎么替换**。

---

## 一、完全通用的部分（可以直接照抄）

| 通用能力 | 说明 |
|---|---|
| Windows 面板 + Linux Agent 架构 | 面板只做 UI 与编排，Agent 常驻自治；电脑关机不影响服务器 |
| SSH `direct-streamlocal` 隧道 | `x/crypto/ssh` 建连后 `client.Dial("unix", "/run/campfire/agent.sock")`，不需要开 TCP 端口、不需要证书 |
| unix socket + 行 JSON-RPC | socket 放 `/run/<app>/`，`RuntimeDirectory=` + `root:<group>` 0660，普通用户进组即可访问 |
| Job 任务模型 | 长操作返回 job id，面板 900ms 轮询日志；所有流水线（下载/同步/备份/重启）都走同一套 |
| `known_hosts` 校验 | 必须把服务器**全部**主机公钥（dss/ecdsa/ed25519/rsa）写进去，LF、无 BOM |
| 用 `worldgenoverride.lua` 而非 `leveldataoverride.lua` | DST 世界生成参数的唯一合法入口 |
| 删 `save` 重新生成世界 | 世界规则只在生成时生效 |
| 从 `scripts.zip` 解包读源码来查键名/标签 | 比查 wiki 准，"代码即文档" |
| 从 `chinese_s.po` 取官方中文 | 分组标题 `STRINGS.UI.SANDBOXMENU.*`、设置项 `STRINGS.UI.CUSTOMIZATIONSCREEN[*]` |
| 模板生成 systemd 单元 | `WorkingDirectory=<install>/bin64`、`Restart=on-failure`、`User=<game user>`、`HOME=<home>` |
| 备份策略 | 定时 tar + 保留 N 份 + 危险操作（删世界/更新模组）前再打一份 |
| 健康检查四件套 | `systemctl is-active`、端口监听、日志关键行（`Online Server Started`）、内存/磁盘 |
| 每轮交付：build → scp → md5 比对 → install → restart → 接口验收 | 见交接说明第六节 |

## 三、换一台全新服务器的"最短路径"

1. 开 ECS（Ubuntu 22.04，2C4G 起）→ 安全组按 2.1 放行 → 创建/绑定 SSH 密钥对。
2. 生成或导入私钥 → 写 known_hosts（4 种主机密钥，LF/无 BOM）。
3. 跑 `deploy/bootstrap.sh`（装 i386 运行库、swap、建 `dst` 用户、装 steamcmd、`app_update 343050`）。
4. 跑加固（禁 root、禁密码、fail2ban、自动更新），建 `ops` 用户并入 `campfire` 组。
5. 上传 Klei Token → 写 `cluster.ini` / `server.ini` → 装 `dst-server`（+ 可选 `dst-server-caves`）→ 开服验证。
6. `platform/bin/campfire-agent-linux` + `deploy/install-agent.sh` → `systemctl status campfire-agent`。
7. 本机改 `panel.json` 的 host/key → 双击桌面图标 → `/api/health` 通 → 世界列表出现 → 收工。

> 其中 1、2、4 的细节都在 `docs\踩坑与解决办法.md`，路径类替换对照上面的表。

## 四、想复用到"别的游戏"时要改什么

- **通用**：面板/Agent 架构、SSH 隧道、Job 模型、备份/重启/等日志就绪的流水线、桌面快捷方式。
- **要重写**：`exec.go` 里的"就绪判定"字符串（这里是 `Online Server Started on port:`）、`mods.go` 的下载与同步路径、`worldgen.go` 的配置格式、`workshop.go` 的 appid 与元数据来源、`clusters.go` 的配置文件格式。
- **要重做**：`worldgen_catalog.json` 的生成脚本（每个游戏的配置系统都不一样）。
- 建议：把"游戏相关"全部收敛到 `internal/agent/game/` 一个包，其它部分保持通用（当前还没拆，是下次重构点）。
