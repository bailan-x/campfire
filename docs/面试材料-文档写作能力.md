## 一句话回答

写过，而且是文档先行：先出一份 2,508 行的设计说明书再写代码，之后每个版本、每次线上事故都追加一章复盘；另有一套任务导向的操作手册（安装、交接、排障、操作规约）。合计约 4,400 行、折合 A4 约 110 页。

## 二、设计说明书怎么搭的结构

四层，从"为什么"到"怎么演进"：

1. **决策层（为什么做、做到什么程度）**
   执行摘要 → 背景与痛点 → 成功标准（如"新服务器到朋友能进 ≤20 分钟""模组更新失败 100% 回滚"）→ 范围 P0/P1/P2（明确写不做什么）→ 术语与 6 条硬约束。
2. **定义层（做成什么样）**
   拓扑与选型 → 功能需求 **FR-01 ~ FR-27**（每条带编号、优先级、验收标准）→ 关键流程 → 数据模型 → API 清单 → 信息架构。
3. **落地层（怎么交付）**
   部署方案 → 排期（M0 五个 spike 先验证命脉，再 MVP）→ 风险表 → 决策记录（每个取舍写"选了什么、为什么不选另一个"）。
4. **演进层（怎么长大）**
   从 §16 起只追加不覆盖：v2.4 实现状态 → v2.5 多世界与 214 项目录 → v2.6 洞穴被生成成地上世界 → v2.7 地上/洞穴设置分开 → v2.8 控制台 → v2.9 分片重连与存档回档 → v2.10 E_ROWID_EXIST → v2.11 优雅关服根治。

每章事故复盘固定五段：**现象 → 证据（日志/包/时间戳）→ 机制（源码行号）→ 修复 → 真机验证数据（种子号、耗时、PANIC 次数）**。

## 三、操作手册怎么组织

任务导向，不按功能罗列。以平台 README 和交接说明为例，目录是"人要完成的事"：

- 第一次部署（前置条件 → 步骤 → 怎么验证成功 → 失败怎么回滚）
- 日常开停与重启（含"停止后等 5 秒再起"这类必须遵守的顺序）
- 加/更/删模组（工坊链接 → 解析 → 安装 → 运行期校验）
- 改世界规则、重建世界
- 备份与回档
- 出问题怎么办（按现象查：连不上、卡注册、分片没生成、模组没生效）

每个任务四段式：**前置条件 → 可复制的步骤 → 验证方法 → 回滚办法**。另外单独一份"坑表"，每条固定写"现象 / 证据 / 机制 / 处置"，按 A–K 分类，遇到同类问题直接查。

## 四、模块与代码结构怎么写

- 目录树 + 每个包一句话职责（`internal/agent` 执行层、`internal/panel` 面板与 RPC、`internal/luaconf` Lua⇄JSON 解析、`cmd/` 两个入口）。
- 一条请求的完整链路图：浏览器 → 面板 HTTP → RPC → SSH direct-streamlocal → Agent Unix Socket → systemd → DST 进程。
- "改哪里要同步改哪里"维护表：例如加一个世界参数，要同时改目录 JSON、proto 字段、前端表单、Agent 写入逻辑。
- 构建发布循环写死：`go vet` / 双平台 build → scp + md5 校验 → install + restart → 验收清单打勾。

目标是：接手的人 30 分钟内能跑起来，并能独立定位一次故障。

## 五、怎么保证文档不过期

- 版本号 + 只追加章节，不覆盖历史结论；
- 每条需求有编号，实现后在"实现状态"章节标状态，能对到代码；
- 文档里写的数字（种子、耗时、错误次数）必须来自真机取证，不拍脑袋；
- 结论当天落盘；改代码必须同步对应章节，否则视为任务没完成；
- 验收清单可勾选，交接时逐条过。

## 七、可能的追问与答法

1. **有没有面向非技术用户的用户手册？**
   坦白说没有出版级的用户手册——产品是单用户工具，面向的是"会一点 Linux 的服主"，等价物是 README 的快速开始 + 交接说明的日常用法。如果要给完全不懂技术的朋友用，我会按任务重写成 10 页图文版。
2. **文档是你写的还是 AI 写的？**
   结构、需求条目、验收标准、证据判定由我定；AI 按结构起草，我逐条校对并用真机输出回填事实。判断标准很简单：文档里每个结论都要能指到一条命令输出或一行源码。
3. **2,500 行会不会过度设计？**
   因为要和 AI 协作，文档就是"可验收的合同"：需求编号→实现→验收清单闭环。事实证明省了返工——洞穴分片错位和 E_ROWID_EXIST 两个疑难故障，都是靠文档里积累的证据链复盘出来的。
4. **文档和代码不一致怎么办？**
   改代码必须同步文档，否则任务不算完成；验收清单逐条勾；文档中的关键数字都标注取证时间。
5. **怎么让长文档可维护？**
   只追加、不覆盖；按"决策/定义/落地/演进"分层，读者按需看；目录带锚点，检索靠关键词表。
